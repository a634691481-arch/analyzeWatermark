# 快手「水印」问题 · 复核台账

> 起因：用户反馈「快手的怎么有水印」，链接 `https://v.kuaishou.com/K23oc0R9`

## 先说结论

**这条水印是烧进画面里的，所有官方流都带着，换下载地址解决不了。**

原适配器注释里写的「`mainMvUrls[0]` 就是无水印源」**是错的** ——
依据是前端 bundle 里的字段名 `srcNoMark`，但那只是前端给播放源起的别名，
不代表流里没水印。

## 证据一：没有任何一条流是「干净」的

两两做带符号亮度差（缩放到 320x180，阈值 d>90），沿时间轴每 3 秒采样：

```
upic vs Ultra     16 个采样点里 14 个 {更亮:0, 更暗:0}（像素级完全一致）
                  仅 t=19s / t=22s 有差异，且「既变亮又变暗」→ 转码/运动偏差，非叠加层
upic vs High      同上
High vs Ultra     全部 0 差异
```

关键点：**如果是「一条带水印、一条不带」，差异会在每个时间点都出现**。
只有个别时间点有差异 = 同一内容的转码差异，不是水印有无的区别。

## 证据二：水印确实存在，位置在顶部左侧

用「区域跨帧相关性 + 空间梯度」定位（8 个时间点抽帧）：

| 区域 | 跨帧相关性 | 平均梯度 |
|---|---|---|
| 全画面（对照） | 0.14 | 5.7 |
| **左上** | **0.44** | **18.0** |
| 左下 | 0.21 | 2.5 |
| 右上 | 0.16 | 5.0 |
| 右下 | 0.12 | 4.0 |
| 底部中 | 0.04 | 12.7 |
| 中间 | -0.00 | 3.9 |

左上区域「相关性高（帧间几乎不变）+ 梯度高（边缘密集）」→ 固定叠加的文字/logo。

细分块扫描确认**只在 y=0 那一行**（y=20/40 行相关性≈0）：

```
     x:   0    32   64   96  128  160
y=  0   0.67 0.75 0.54 0.76-0.05-0.06   ← 只有这一行稳定
y= 20   0.04 0.02 0.03-0.02-0.02-0.04
y= 40   0.04-0.02-0.04-0.01 0.03 0.06
```

换算到 720p 原分辨率：大致是 **x 0~460, y 0~90** 的一条。

原分辨率下该区域平均横向梯度 **15.79**，而中间/右下对照区仅 **1.01 / 0.88**：

```
左上水印区  平均横向梯度=15.79   ← 全是边缘，文字/logo
中间对照区  平均横向梯度=1.01
右下对照区  平均横向梯度=0.88
```

**同一个水印在两条件流（h264 720p / hevc 1080p）里都在。**

## 为什么最终没改地址选择

| 选择 | 结果 |
|---|---|
| `mainMvUrls[0]` h264 720p | ✅ 浏览器 `<video>` 能直接预览；水印一样存在 |
| `representation[2]` hevc 1080p | ❌ 分辨率更高，但 hevc 浏览器基本放不了、Windows 需另装解码器 |

既然水印在所有流里一致，**就没有理由为了一个同样带水印的流去牺牲可播放性**。
所以维持 h264 720p，只是把错误注释改正、把实测结论写进代码注释，避免后人再踩。

## 一句话给用户的解释

这条水印是随内容一起下发的（作者用 AI 工具生成时就烧进了画面，或平台 AI 计划加的），
不是快手在下发时叠上去的，所以**任何下载方式都拿不到无水印版本**。
工具能保证的是「拿到平台提供的最高可用源文件」，不能凭空去掉画面里已有的内容。
